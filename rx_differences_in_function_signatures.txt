This document contains differences in function signatures introduced
by the work to use RustworkX for GerryChain.

=> Note that this analysis does not take into account any changes to
   parameter default values - whether they have gone from required
   to optional or whether the default value has changed...

   It also does not take into account changes to class definitions.

file: gerrychain/tree.py

    * File(s) deleted from RX codebase

      => The file, tree.py, has been removed and its contents have been 
         moved to one of two new files under a new directory, "tree".
         Note that users can (and should) continute to import tree, so
         there should be no impact on legacy code from moving functions 
         to new files.

         The reason for moving functions to two files is to make it 
         easier to understand what is going on.  Functions that are
         about splitting off districts from a graph (bipartition-ing)
         were kept together in a new file, bipartition_tree.py, while
         functions that were about creating spanning trees were 
         put in their own file, spanning_tree.py.

file: gerrychain/tree/spanning_tree.py

    * New file(s) added to RX codebase

      => The file, tree/spanning_tree.py is new.  

         This was part of the refactoring of tree.py into several
         distinct files to make it easier to understand and 
         maintain the codebase.  The file tree.py no longer exists
         and instead there is a directory, tree, with python 
         files, but with an __init__.py file that defines the
         same interface for "tree" as in the old codebase.

         This file, spanning_tree.py, contains functions that 
         create spanning trees.

    * Function(s) moved from one file to another 
      => moved from tree.py to tree/spanning_tree.py

        * def random_spanning_tree(graph, region_surcharge):
        * def uniform_spanning_tree(graph, region_surcharge):

    * Addition of paremter(s)
    * Deletion of paramter(s)

        * def uniform_spanning_tree(graph, region_surcharge):
          => Added region_surcharge, removed choice

          NEW => def uniform_spanning_tree(graph, region_surcharge):
          OLD => def uniform_spanning_tree(graph, choice):

        * Note: The rationale for changing the parameters was to unify
                the function signatures for the two different ways of
                creating a spanning tree, which makes using the 
                spanning tree functions as parameters more straight-forward.
                Previously, one had to create a partial function to 
                bind the different parameters.

    * Impact on users:
        * There should be minimal to no impact on users as the changes
          are to internal code.  However, if a user directly called a 
          spanning tree function, then they would need to make sure that
          they used the correct parameters.
